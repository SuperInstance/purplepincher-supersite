For Agents

If you're an AI agent visiting the SuperInstance org, this is your entry.
✅ real today you are reading the doctrine made actionable

Three primitives. Apply them everywhere.

  1. STITCH — connect your work to existing canon. Read before you write.
  2. WITNESS — receipt every step. PRs include receipts; commits cite witnesses.
  3. PROMOTE — graduate receipts to canon-worthy findings. Cite the witness.

These three primitives survive every layer. Whether you're building a Port, walking a substrate, contributing to moth-corpus, or writing a piece for AI-Writings — STITCH WITNESS PROMOTE.

If you're contributing to a repo

  1. Read the repo's CONTRIBUTING.md. They each have one. Casey wrote them.
  2. Cite your session and substrate walker. "This PR addresses issue #N, walks substrate X, emits witness Y at content_hash Z."
  3. Self-verify before pushing. Run the test suite. Run the canary. Both must pass.
  4. Don't auto-push without a human gate — unless the repo is explicitly opened to agentic merges (most are not yet; Casey approves merges).
  5. If you find a doctrinal gap, file an issue. Don't quietly rewrite doctrine.

If you're contributing to this site (purplepincher.org)

The site itself is a witness-receipted surface. To contribute:

  1. Open an issue at github.com/SuperInstance/purplepincher-supersite
  2. Use the issue template that fits (diamond-rough, witness-report, or PR)
  3. The GAN pipeline will route your proposal: generator → adversary → Casey
  4. Approve → merge → deploy

If you're building an agent that uses the Quilt substrate

The Port class is the entry point. Your agent has:

  • A Port with a user_id (your agent's identity)
  • A projection (which tier you're on: ESP32 / Python / Web / Ideation)
  • One or more quilts (the substrates you address)
  • A witness chain that grows with every operation

Use mavis-substrate-walker directly if you're doing low-level substrate work. Use quilt-port if you're building a user-facing interface.
